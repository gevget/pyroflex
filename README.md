# ПИРОФЛЕКС — локальная версия сайта

## Запуск

Требуется Node.js, установка пакетов не нужна. Из корня проекта выполните:

```powershell
node tools/serve-local.mjs
```

Откройте `http://127.0.0.1:4173/`. Для проверки страницы политики используйте `/privacy/`. Открытие через HTTP важно для корректной работы переходов и ресурсов; хостинг должен отдавать файлы проекта с сохранением относительных путей.

## Публикация в GitHub Pages

GitHub Actions собирает автономный сайт в `dist/` и публикует его по адресу `https://gevget.github.io/pyroflex/`. Для локальной проверки итоговой сборки выполните `node tools/build-pages.mjs` и откройте `dist/index.html` через локальный HTTP-сервер. При изменении страниц или стилей сборка автоматически переносит только используемые ресурсы и добавляет манифест, офлайн-кеш и адаптивные значки PWA. Исходная выгрузка платформы, временные файлы и печатные макеты в публикацию не входят.

## Состав проекта

- `index.html` — новая автономная семантическая версия главной страницы.
- `contacts.html`, `documents.html` — контакты команды и архив из 48 локальных PDF с фильтром по продукту/системе и типу документа; для английской версии доступны `/en/contacts.html` и `/en/documents.html`.
- `partners.html`, `services.html` — самостоятельные страницы для партнёров и услуг; английские версии доступны в `/en/`.
- `products/` — восемь продуктовых и две системные страницы; ссылки на сопутствующие материалы проверены по каталогу.
- `mk101/index.html` — внутренняя страница производителя МК101; пункт MK101 добавлен в навигацию русской и английской версий сайта.
- `mk101/copy.html` — независимая точная копия страницы для сверки и будущих правок контента.
- [Аудит связей продуктов](docs/RELATED_PRODUCTS_AUDIT.md) — сверка сопутствующих материалов по каталожным MD-файлам и локальным URL.
- `assets/site/site.css`, `site.js` — собственные стили и поведение компонентов `pf-*`.
- `assets/site/fonts/`, `fonts.css`, `images/` — локальные шрифты Montserrat и используемые изображения.
- `privacy/index.html` — временная локальная страница политики; юридический текст ожидает утверждения владельцем.
- `reference.html` и исходные каталоги — сохранённая копия выгрузки для сверки исходной композиции и контента.
- `SITE_GUIDE.md`, `docs/DESIGN_SYSTEM.md` — визуальная спецификация и правила развития.
- `docs/MIGRATION_AUDIT.md`, `ANCHOR_MAP.md`, `LINK_AUDIT.md` — инвентаризация переноса, карта якорей и аудит ссылок.
- `tools/audit-standalone.mjs` — локальная проверка ID, ссылок и ресурсов.
- `tools/optimize-active-images.mjs` — создание WebP-копий крупных изображений активных страниц без удаления оригиналов.
- `tools/build-pages.mjs` — автономная сборка для GitHub Pages, включая необходимые локальные ресурсы и PWA-метаданные.
- `sw.js`, `assets/site/pwa-register.js` — офлайн-кеш страниц и локальных медиа; большие PDF документы остаются сетевыми загрузками.
- `.github/workflows/pages.yml` — сборка и автоматическая публикация при обновлении ветки `main`.
- `docs/RESPONSIVE_AUDIT.md` — результаты проверки адаптива, меню, фильтров, сертификатов и оптимизации изображений.

## Проверки

Запустить структурный аудит:

```powershell
node tools/audit-standalone.mjs
```

Аудит проверяет активные HTML-страницы, уникальность ID, внутренние переходы, локальные ресурсы и отсутствие платформенных строк в HTML/CSS/JS автономной версии. Отчёт создаётся в `docs/LINK_AUDIT.md` и `docs/audit-result.json`.

## Ограничения перед публикацией

- Контактная форма автономной страницы подготавливает письмо через `mailto:`; для реальной отправки нужен согласованный серверный обработчик.
- Утвердить текст политики конфиденциальности и проверить согласие на обработку данных.
- Перед публикацией пройти визуальную сверку всех контрольных ширин и кликами проверить интерактивные элементы.

## Структура страниц

Сейчас сайт включает главную RU/EN, восемь продуктовых страниц, две системные страницы, страницы контактов, документов, партнёрам и сервисов на RU/EN, а также политику конфиденциальности. Другие отдельные страницы добавлять по мере появления самостоятельного пользовательского сценария и подтверждённого контента.
